# 重现验收场景草案

以下为将来对原版补证和对重现应用验收的场景，**本轮没有执行这些完整Case**。已执行的局部操作只见 `catalog/observations.json`。所有Case必须先绑定应用版本/二进制SHA、配置、数据目录、摄像设备及屏幕环境。

## 通用Case结构

每个Case包含：`前置状态与数据 → 事件链 → 每个节点断言 → 终态观察 → 证据`。事件是页面上的一个操作；检测事件/时钟输入作为独立测试条件，不混称真实页面行为。记录原始时间与有效采样时长，必要时区分单调时钟和墙钟。预定断言失败就保留失败，不为制造PASS修改它。

## 自动化与人工验证分工

- 核心单测：可控时钟驱动到期/推迟/自然休息/暂停恢复；固定连续帧检测事件验证阈值、防抖及统计公式；延迟/旧回调验证取消和仲裁；持久化写入中断。
- 系统集成：macOS会话/空闲/窗口适配器、设备权限、开机启动、通知和多屏位置；不能只Mock后声称真实系统行为通过。
- UI验收：点击真实按钮，逐节点保存画面/状态/时间；相机成功路径使用真实相机；原版长周期行为不靠修改断言缩短。
- 最终报告分别记录源码检查、单测、构建、打包、安装和真实UI结果。所有范围内Case均执行并通过才准出。
- C29的包扫描不能代替C30的实机执行；P0先验证最小arm64链路，P1起持续arm64构建。Intel与Universal包不在默认首版准出范围。

历史/平台不明项S045/S049/S050/S055-S060/S064-S066保持延后；若后来纳入范围，增加对应Case及证据，不能在实现时悄悄加上。
