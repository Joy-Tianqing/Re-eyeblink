# 完整重现计划与当前进度

目标是重现本机 eyeblink 3.7.4.0 的实际 Mac 行为，中文优先，并原生运行于 Apple Silicon。界面按 apple-design 和 Apple macOS HIG 重做。已有可运行 App；当前仍不能声明完整复刻完成。

新增增强需求（2026-10-21）：用户的摄像头位于右侧约15–30°，希望自然看屏幕时仍可靠识别。侧置识别已按[独立设计](side-camera-design.md)接入原生相机流程：分眼坐姿校准、眼睑轮廓/姿态、运动抑制与有效画面门槛；默认开启，原算法可作对照。164项完整/73项发布专项测试通过，新增19项增强测试；真实预览约30FPS。它属于原版之外的增强，不把复刻组件或合成轮廓对照通过等同新算法准确率通过；人工校准、计数与完整测量仍待验收，旧历史不重算。

## 已落地的技术选择

使用 SwiftUI / AppKit、AVFoundation、Swift Charts、ServiceManagement，最低 macOS14。OpenCV4.4.0只编译core/imgproc/video arm64静态库；旧Intel dylib、Qt和历史上传器不参与新App运行。人脸检测使用原版24层int8权重与对应历史libfacedetection实现；5点预测器在Swift读取原版dlib模型，光流使用恢复的原版Farneback参数及时间状态机。

采用一个相机租约、一套调度状态机、一套暂停原因集合。预览/训练/测量不能各自开相机；晚到的帧同时检查output身份、相机代数和测量ID。界面与设备回调分离。退出等待落盘，清空历史期间阻止新测量进入旧存储代数。

会话配置/启停与有序帧分析使用独立串行队列，前者先撤掉旧视频delegate再等待后者收尾，避免持续帧回调阻塞停止请求；设备所有权仍只有一个入口。本机两轮真实采集中退出收尾约0.158/0.096秒，先前诊断约40秒的队列等待已取得修复证据。

这里的本质复杂度是相机所有权、系统权限、检测噪声、不同提醒的时序和数据生命周期。重复计时器、多个相机管道、用户暂停与自动暂停互相覆盖属于应消除的偶然复杂度。
